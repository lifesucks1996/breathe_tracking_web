❌ TROUBLESHOOTING - PROBLEMAS COMUNES
════════════════════════════════════════════════════════════════════════════════

PROBLEMA 1: "No se encontró serviceAccountKey.json"
──────────────────────────────────────────────────

❌ ERROR:
    FileNotFoundError: [Errno 2] No such file or directory: 
    'serviceAccountKey.json'

✅ SOLUCIÓN:
    1. Descarga el archivo desde Firebase Console:
       https://console.firebase.google.com → biometria-g3 → Configuración → 
       Cuentas de Servicio → Generar nueva clave
    2. Colócalo en: scripts_python/serviceAccountKey.json
    3. Vuelve a ejecutar el script


PROBLEMA 2: "ModuleNotFoundError: No module named 'firebase_admin'"
─────────────────────────────────────────────────────────────────

❌ ERROR:
    ModuleNotFoundError: No module named 'firebase_admin'

✅ SOLUCIÓN:
    Ejecuta:
    pip install firebase-admin tqdm
    
    Si sigue fallando:
    pip install --upgrade firebase-admin tqdm


PROBLEMA 3: "ConnectionError" o "Error de conexión a Firebase"
───────────────────────────────────────────────────────────────

❌ ERROR:
    google.api_core.exceptions.GoogleAPICallError
    Connection refused

✅ SOLUCIÓN:
    1. Verifica conexión a internet
    2. Verifica que serviceAccountKey.json es válido
    3. Verifica que el proyecto "biometria-g3" existe en Firebase
    4. Espera unos minutos y vuelve a intentar


PROBLEMA 4: "El panel web muestra sin resultados"
──────────────────────────────────────────────────

❌ SÍNTOMA:
    Panel abre pero no muestra sensores

✅ SOLUCIÓN:
    1. Recarga la página (F5)
    2. Abre DevTools (F12) → Pestaña Console
    3. Busca errores rojos (❌)
    4. Verifica en Firebase que los documentos se crearon:
       https://console.firebase.google.com → biometria-g3 → 
       Firestore Database → Colección "Sensores"
    5. Vuelve a ejecutar: python prueba_carga_sensores.py


PROBLEMA 5: "Puerto 8000 ya está en uso"
─────────────────────────────────────────

❌ ERROR:
    Address already in use

✅ SOLUCIÓN - OPCIÓN A:
    Usa otro puerto:
    python -m http.server 8001
    
    Luego abre en navegador:
    http://localhost:8001/breathe_tracking_web/src/admin_sensors.html

✅ SOLUCIÓN - OPCIÓN B:
    Encuentra y cierra qué está usando puerto 8000:
    netstat -ano | findstr :8000
    taskkill /PID <NUMERO> /F


PROBLEMA 6: "Los botones de paginación no funcionan"
────────────────────────────────────────────────────

❌ SÍNTOMA:
    Hago clic en "Siguiente" pero no cambia de página

✅ SOLUCIÓN:
    1. Abre DevTools (F12)
    2. Pestaña Console → Busca errores
    3. Recarga la página (Ctrl+F5 para limpiar caché)
    4. Vuelve a intentar

📊 ESTRUCTURA DE UN SENSOR SIMULADO
════════════════════════════════════════════════════════════════════════════════

Cada sensor tiene esta estructura en Firebase:

{
  "id": "SENSOR_001",                    ← ID único
  "nombre": "Sensor 001",                ← Nombre
  "ubicacion": "Parque Central, Gandía", ← Ubicación
  "coords": [38.9640, -0.1850],          ← [Latitud, Longitud]
  "estado": "normal",                    ← Estado del sensor
  "bateria": 87,                         ← % Batería
  "temperatura": 22.5,                   ← Temperatura (°C)
  "co2": 412,                            ← CO₂ (ppm)
  "ozono": 0.045,                        ← Ozono (ppm)
  "ultima_conexion": "12:34",            ← Última conexión (HH:MM)
  "hasIncident": false,                  ← ¿Tiene incidencia?
  "active": true                         ← ¿Activo?
}

VARIABLES:
──────────
• 7 sensores reales (ADS133, AKMSF134, LMN789, etc.)
• 200 sensores simulados (SENSOR_001 a SENSOR_200)
• ~15% con incidencias (hasIncident: true, color rojo)
• ~1% inactivos (active: false, color gris)
• ~84% normales (color azul)

❓ PREGUNTAS FRECUENTES
════════════════════════════════════════════════════════════════════════════════

P: ¿Cuánto tiempo tarda la simulación?
R: Aproximadamente 2-3 segundos para cargar los 200 sensores.

P: ¿Puedo ejecutar el script varias veces?
R: Sí. Los sensores se sobrescriben (actualización), no se crean duplicados.

P: ¿Cuáles son las "7 sensores reales"?
R: ADS133, AKMSF134, LMN789, XYZ001, BTH202, OFF_99, OLD_00

P: ¿Por qué algunos sensores aparecen en rojo?
R: Tienen incidencias detectadas (hasIncident: true)

P: ¿Por qué algunos aparecen en gris?
R: Están inactivos (active: false)

P: ¿Puedo cambiar la cantidad de sensores simulados?
R: Sí. En scripts_python/prueba_carga_sensores.py, línea 28:
   NUM_SENSORES = 200  ← Cambia este número

P: ¿Dónde se almacenan los datos?
R: En Firebase Firestore, colección "Sensores"

P: ¿Se eliminan después de cierto tiempo?
R: No. Los datos permanecen hasta que los borres manualmente.

P: ¿Puede acceder alguien más a estos sensores?
R: Sí, si tiene credenciales Firebase (serviceAccountKey.json)

P: ¿Cómo veo los detalles de un sensor?
R: Haz clic en "Ver" en la lista o haz clic en un marcador del mapa.

🎓 NOTAS TÉCNICAS
════════════════════════════════════════════════════════════════════════════════

ARQUITECTURA:
  • Backend: Python con Firebase Admin SDK
  • Frontend: HTML/CSS/JavaScript vanilla
  • Base de datos: Firebase Firestore
  • Visualización: Leaflet.js + Chart.js
  • Servidor web: Python SimpleHTTPServer (puerto 8000)

FLUJO DE DATOS:
  1. Script Python genera 200 sensores con datos aleatorios
  2. Se cargan en Firebase Firestore (colección "Sensores")
  3. Frontend carga datos desde admin_sensors_data.js (7 reales + 200 simulados)
  4. Se renderizan con paginación (20 por página)
  5. Se muestran marcadores en mapa Leaflet
  6. Se generan gráficos con Chart.js

PERFORMANCE:
  • Latencia promedio: ~230ms por sensor
  • Velocidad: ~10 documentos/segundo
  • Carga total: 2-3 segundos
